# 办公室环境层次升级设计

- 日期：2026-04-15
- 状态：已确认设计，待用户审阅
- 范围：`OfficeScene`、`OfficeRoute`、`OfficeHUD`、`RoomPanelHost`、`FloatingChatBox`
- 主线：氛围演出优先
- 视觉目标：高级数字感

## 1. 背景

当前数字办公室已经具备基础地图、房间切换、角色存在感和外层 UI 容器，但整体观感仍偏“功能可用的平面场景”。房间之间的关系主要依赖色块和标签，外层 HUD、房间面板和聊天框也还没有完全收束到同一套数字办公室视觉语言中。

本轮升级不改变办公室的核心玩法和交互路径，重点是把空间从“地图”推进成“正在运行的数字工作系统”，让用户一进入办公室就能感受到更强的系统活性、环境生命感和统一的高级数字氛围。

## 2. 设计目标

### 2.1 主目标

1. 优先提升办公室的氛围演出，让场景具备明显的高级数字感。
2. 在氛围升级的同时，顺带强化空间纵深和房间设备存在感。
3. 让 `OfficeScene`、HUD、房间面板壳子和聊天框属于同一套视觉系统。
4. 保持现有房间触发、角色移动和交互流程不受影响。

### 2.2 非目标

1. 本轮不重写办公室交互逻辑。
2. 本轮不引入新的复杂素材依赖或整套美术资源替换。
3. 本轮不扩展新的房间功能。
4. 本轮不做像素级视觉自动化验证。

## 3. 体验结论

### 3.1 用户第一眼感受

用户进入办公室后，应首先感受到这里像一个未来数字指挥中心，而不是普通网页上的房间卡片集合。空间需要显得持续在线、持续运转，具备屏幕辉光、信号流、扫描纹和低频动态反馈，但整体表现必须克制，不可退化成过度炫技的赛博夜店风格。

### 3.2 本轮主线排序

本轮按以下优先级推进：

1. 氛围演出
2. 空间层次
3. 房间物件细节

### 3.3 统一原则

1. 场景是主舞台，外层 UI 只做延伸和陪衬。
2. 所有新增演出都服务于“系统正在运行”的感受。
3. 每个房间可以有局部差异，但必须属于同一套数字办公室主题。

## 4. 总体方案

本轮采用“分层环境系统”方案，而不是只在现有场景上叠一层特效，也不做全量舞台化重构。

原因如下：

1. 纯特效叠层虽然成本低，但容易显得像贴了滤镜，无法同时解决空间纵深和统一性问题。
2. 全量舞台化重构虽然视觉冲击更强，但当前版本的交互密度不足以支撑过重的主题表达，容易喧宾夺主。
3. 分层环境系统可以在保留现有交互结构的前提下，同时提升氛围、纵深和设备存在感，是当前版本性价比最高的方向。

## 5. `OfficeScene` 设计

### 5.1 环境分层

`OfficeScene` 的渲染升级按以下五层组织：

1. 远景环境层
2. 路径信号层
3. 房间设备层
4. 动态演出层
5. 前景遮挡层

场景主文件负责组装和驱动这些视觉层，而不是在单一文件中直接堆叠所有绘制细节。

### 5.2 远景环境层

远景环境层延续当前暗色基底，但升级成更接近数字控制中心地面的感觉。其核心元素包括：

1. 大面积低透明度径向辉光。
2. 更精细的冷色网格线。
3. 少量琥珀节点与辅助光斑，用于打破纯冷色单调感。
4. 斜向扫描带和边缘暗角，用于形成空间包裹感。

这一层的目标不是增加信息密度，而是建立统一气质和纵深背景。

### 5.3 路径信号层

当前房间之间的连接以静态线条为主。本轮将它升级为“数据管线”表达：

1. 主路径为深色发光轨道。
2. 轨道中央增加细流光段，表达信号传输。
3. 玩家静止时路径依然保留低频动态。
4. 不改变路径几何布局，避免影响已有地图认知。

该层用于强化“办公室是运行中的系统，而不是静态地图”这一感受。

### 5.4 房间设备层

每个房间在不增加复杂交互的前提下，补入少量高辨识度的数字设施：

1. 主办公室：中央控制台、状态屏、环形仪表。
2. 会议室：大屏幕、任务投递灯、玻璃隔断感。
3. 人事部：记忆档案柱、数据柜、纵向扫描线。
4. 培训室：技能终端、训练光柱、课程屏。
5. 休息间：低频环境灯、状态恢复仓或休息舱抽象形态。

这些设施以环境叙事为主，不承担新的业务逻辑，只用于提升房间存在感和主题分工。

### 5.5 动态演出层

动态演出层用于让空间“活着”，但必须严格控制频率和幅度。允许的表现包括：

1. 小粒子点漂移。
2. 屏幕待机闪烁。
3. 边缘呼吸灯。
4. 细扫描线或短促信号扫过。

限制如下：

1. 不使用高频闪烁。
2. 不使用大面积强对比跳色。
3. 不干扰角色识别、房间标签和可点击区域。

### 5.6 前景遮挡层

前景层主要用于补足空间包裹感，包括：

1. 轻量玻璃反射。
2. 角落结构边框。
3. 半透明前景遮罩。

该层不做真实碰撞或复杂遮挡计算，只通过视觉组织强化人物处于空间内部的感受。

## 6. 外层 UI 统一设计

### 6.1 `OfficeRoute`

`OfficeRoute` 的外框从纯容器升级为“观察窗”表达。重点包括：

1. canvas 外框更像数字系统观察窗，而不是普通页面卡片。
2. 标题 ribbon、环境边框和主画布材质统一到同一套玻璃化数字语言。
3. 外框保留克制，不与场景内部抢主视觉。

### 6.2 `OfficeHUD`

`OfficeHUD` 保留现有信息结构，但视觉升级为“数字员工状态终端”：

1. 保留名字、状态、房间、控制方式等核心信息。
2. 材质改为冷色玻璃底、弱扫描纹、边缘辉光和局部琥珀强调。
3. 强调可读性，不通过增加更多指标来制造复杂感。

### 6.3 `RoomPanelHost` 与房间面板壳子

房间业务内容仍然按房间差异化保留，但其承载容器统一收束为“悬浮玻璃终端”：

1. 统一边框、圆角、阴影、辉光和顶部状态条。
2. 房间差异主要通过 accent 色和局部装饰表达。
3. 避免不同房间面板像不同产品拼接在一起。

### 6.4 `FloatingChatBox`

右下角聊天框维持当前产品职责，但外观升级为办公室通信终端：

1. 与 HUD、房间面板共享同一主题 token。
2. 输入区更接近指令终端，而不是客服对话框。
3. 保持常驻但不成为视觉噪音。

## 7. 视觉系统与数据组织

### 7.1 场景视觉配置

为避免 `OfficeScene` 进一步膨胀，本轮新增的场景表现应抽成独立配置和辅助函数，建议至少覆盖：

1. 房间视觉配置
2. 环境辉光配置
3. 路径信号配置
4. 动态演出参数
5. 前景装饰配置

主场景文件负责读取和应用这些配置，而不是散落硬编码。

### 7.2 UI 主题 token

React 侧新增一套办公室主题常量，用于统一：

1. 基础底色
2. 描边颜色
3. 阴影
4. 辉光
5. 房间 accent
6. 扫描纹理强度
7. 面板材质层级

这套 token 需要支持房间切换时的轻联动，但联动必须是低幅度、低打扰的。

## 8. 退化与风险控制

所有新增内容都定位在表现层，不得影响当前主链路功能。

### 8.1 退化原则

1. 动态粒子失效，办公室仍可进入与移动。
2. 主题联动失效，HUD 和面板仍可读可操作。
3. 环境装饰缺失，房间触发逻辑仍然正常。
4. 新增样式必须允许在功能不变的前提下回退。

### 8.2 风险控制

1. 尽量基于 Phaser 原生图形绘制、现有 React 样式和已有结构实现。
2. 不引入新的大型资源依赖。
3. 不改变房间触发系统、移动系统和对话主链路的行为边界。

## 9. 测试策略

本轮按“配置解析 + 组件表现”两层验证，不做像素级快照。

### 9.1 场景侧测试

优先覆盖：

1. 房间视觉配置存在且可解析。
2. 新增环境层配置具备完整结构。
3. 房间与视觉 accent 的映射关系稳定。

### 9.2 React 侧测试

优先覆盖：

1. `OfficeRoute` 仍能同时挂载场景与外层 UI。
2. `OfficeHUD` 在房间切换时仍正常渲染，并带有新的主题标识。
3. 房间面板容器和聊天框使用统一的主题语言入口。

### 9.3 实施方式

实现过程按 TDD 推进：

1. 先写配置和主题测试。
2. 验证失败。
3. 再补最小实现。
4. 最后做结构整理。

## 10. 完成标准

本轮完成后，用户进入办公室时应满足以下结果：

1. 第一眼能感受到明确的高级数字感。
2. 场景在静止状态下依然有“系统在线”的生命感。
3. 房间之间既统一又有分工，不再只是不同颜色的卡片。
4. 角色、HUD、房间面板和聊天框属于同一个系统。
5. 现有交互链路不出现行为回归。
